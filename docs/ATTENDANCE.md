# Attendance, ready checks and reviewed DKP

## Join and respond

1. Open **Linkshell > HNM > Open camps**, or run `//lootryx camp` on Windower
   (`/lootryx camp` on Ashita).
2. Open the correct session and choose **Join camp**. Being in the game party
   or having the addon loaded does not join you automatically.
3. When a scheduled check opens, choose **Present and ready** only if you were
   present and available for that period. Otherwise choose **AFK / unavailable**.
   Respond before the displayed deadline. The website's **Live attendance** screen
   accepts responses to the same session.
4. Review your recorded response and estimated points. Estimates become spendable
   only after an officer reviews and posts the session.
5. Choose **Leave camp** when leaving. Previous responses remain recorded; future
   periods and kill participation are subject to the session's rules.

![Scheduled attendance response](screenshots/09-ready-check.png)

The service schedules the checks. For example, an Expo policy can use 30-minute
periods and five-minute response windows. Use the rules shown for your session,
not a timing assumption from this guide. Joining late does not qualify you for
an entire period that already started. Missed or disputed periods need officer
review; the client cannot backdate a response.

## Start and manage a session

Authorized officers can choose **All camps > Start camp**, enter the target,
choose a start time, select LG, Expo or No DKP rules, and select the wallet.
Review the displayed policy before confirming. An unscheduled camp does not
require a previously scheduled calendar event. Starting immediately does not
create a retroactive early-attendance bonus.

**Ready check now** opens an immediate availability check. It does not award
DKP or replace the scheduled attendance checks.

At the end, choose **Killed**, **Missed claim** or **End without kill**. For a
kill, explicitly select the members who participated. No kill is detected
automatically. Ending retains the observations and does not post DKP.

Review each member's attendance and document any corrections, including assigned
scouts or transfers. Then choose **Review and post DKP**, inspect the totals,
enter a review note and confirm. The service checks the reviewed revision, so
an old review cannot silently overwrite a newer decision. Refresh and review
again if someone changes the session while you are reviewing it.

![Officer review before points become spendable](screenshots/10-review-points.png)

## Delivery and recovery

- Keep the addon connected and camp refresh enabled in notification preferences.
  Chat alerts and background refresh are separate preferences.
- The addon polls the service. Notifications can be delayed by connectivity,
  disabled refresh or another request. A local countdown does not extend the
  server's deadline.
- If a response is not confirmed, refresh and inspect the recorded state before
  retrying. Do not assume a failed request earned credit.
- Use the website if the addon cannot connect. Both clients use the same records.
- Another joined linkshell session can prevent joining here. Leave that session
  through the appropriate linkshell or the website first. The same attendance
  time cannot receive duplicate credit across overlapping sessions.
- Responses are member attestations, not proof of continuous game presence.

## Legacy event check-in and snapshots

Calendar event check-in and roster capture remain available as a separate flow.
A snapshot requires an open event check-in and records observed names; it is not
a scheduled ready-check answer or an automatic DKP award. If capture says no
check-in is open, an authorized officer must open the event's check-in, or start
a camp session when that is the intended attendance flow.
